## 1. 상위목표

> **백엔드 면접에서, my-recipe의 코드와 설계 결정을 AI 없이 내 말로 설명하고 꼬리질문에 답할 수 있는 상태가 된다.**

- 목적: 취업 (회사 규모는 고려하지 않음). 평가자: 면접관
- 대상: 대구·구미 Java/Spring 웹 개발 공고 (SI·SM·ERP·솔루션 중심)

**완료 기준**: 파일을 아무거나 하나 무작위로 열었을 때, AI 없이 ① 무엇을 하는지 ② 왜 이렇게 짰고 다른 선택지는 무엇이었는지 ③ 바꾸면 어디가 깨지는지를 말할 수 있다. 커밋마다 이 세 질문으로 확인하고(AGENTS.md 4장 6번, `notes/EXPLAIN_CHECK.md`), 이것을 핵심변수로 관리한다(3장).

**기술 채택 기준**: 면접에서 꼬리질문 3번을 버틸 수 없는 기술은 넣지 않는다.

### 공고 근거 요약

- 전형: 코딩테스트·과제가 있는 곳은 없었다. 모두 서류 + 면접 1~2회이고, 일부는 포트폴리오를 필수로 낸다. → GitHub와 면접에서의 설명이 전부다.
- SQL: 거의 모든 공고가 요구한다 (SELECT·JOIN·집계 수준). MyBatis는 본문 4건에 나왔고 JPA는 0건이었다.
- 화면: HTML/CSS/JS로 화면을 구현·수정할 수 있어야 한다.
- 운영: 로그로 오류 분석, 데이터 정합성 확인, 실서버 배포, 작업 기록·매뉴얼.
- 외부 연동: 결제·SMS·지도 API, 사내 REST, 시스템 간 인터페이스. → S3 presigned URL 업로드가 이 질문의 사례가 된다.
- 코드 이해: 기존 소스를 읽고 구조를 파악하는 능력, AI가 짠 코드를 이해·수정·검증하는 능력.
- 요구사항 정리: 담당자의 요청을 듣고 무엇을 만들지 정리하는 능력.
- 자격증: 정보처리기사 우대가 5건 → 프로젝트와 별도로 준비한다.

## 3. 핵심변수: 설명 확인 통과 여부

> 2026-11-08 수정. 처음에는 데이터 접근 방식을 핵심변수로 골랐지만, 상위목표("AI 없이 설명")를 가장 크게 좌우하는 것은 기술 선택이 아니라 **AI가 쓴 코드를 정말 이해하고 넘어가는가**다. 데이터 접근 방식은 주로 답안지 2번에만 영향을 주고, 이해 여부는 답안지 전체를 좌우한다.

- **지표**: `notes/EXPLAIN_CHECK.md`에서 "다시 답한 날"이 비어 있는 질문 수
- **멈춤 규칙**: 미해결 질문이 **3개 이상**이면 새 기능·새 단계 작업을 시작하지 않고, 그 질문부터 코드와 AI 설명을 보지 않고 다시 답한다. 3개 미만이 되면 다시 진행한다
- **우선순위 규칙**: 일정이 밀리거나 둘 중 하나를 골라야 하면, 새 기능·기술보다 "설명할 수 있는 상태"를 지키는 쪽을 먼저 택한다

## 4. 기술 결정: 데이터 접근 방식 → JPA + MyBatis 병행 (답안지 2번을 채우는 수단)

| JPA | MyBatis (읽기 전용) |
|---|---|
| 쓰기 전부, ID 단건 조회, 상세 조회, **일반 레시피 목록**(N+1을 직접 겪고 fetch join으로 해결) | **재료 검색 목록**, **인기 재료 TOP 10** (3단계부터) |

세부 규칙은 `CODE_CONVENTION.md` "Repository"를 따른다. MyBatis로는 쓰지 않고, JPA로 쓴 직후 같은 트랜잭션에서 MyBatis로 조회하지 않고, `#{}`만 쓰고, 실행 계획을 확인한 뒤 반영한다. 스키마는 Flyway로 직접 작성하고 `ddl-auto: validate`.

**면접 답변 초안**: "단순 CRUD와 일반 목록은 JPA로 생산성을 챙기면서 N+1을 직접 겪고 해결했고, 검색·집계처럼 SQL을 통제해야 하는 조회는 MyBatis로 직접 썼습니다. 쓰기는 JPA로만 해서 영속성 컨텍스트와 DB가 어긋나지 않게 했습니다."

**꼬리질문 대비**: 영속성 컨텍스트·1차 캐시·dirty checking, flush 시점, N+1과 해결법(fetch join·`@EntityGraph`·batch size), 지연·즉시 로딩 / `#{}`와 `${}`, resultMap, 동적 SQL / 두 기술을 함께 쓰는 이유와 트랜잭션 안 정합성 / 인덱스 설계와 실행 계획 읽기
